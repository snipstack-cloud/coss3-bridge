# Ферма опытов: прогоны в контейнерах

Контейнер — это ОДНА копия игры под Wine со своим мостом и своей моделью.
Сборка образа `coss3:2` уже сделана, игра запечена внутрь, мост приезжает из git
при старте.

## Два правила про ресурсы — НАРУШАТЬ НЕЛЬЗЯ

**1. Одновременно живых контейнеров — не больше ЧЕТЫРЁХ.** Каждый это отдельная
копия игры под Wine плюс свой поток запросов к модели: пятый не ускоряет серию,
а отнимает у остальных процессор и деньги. Нужно больше копий — гнать волнами по
четыре, а не поднимать всё разом. Проверять ДО запуска, а не после:

```bash
docker ps --filter name=coss3- --format "{{.Names}} {{.Status}}" | tee /dev/stderr | wc -l
```

**2. Отыграл и результат уехал — гасить.** По умолчанию контейнер держится живым
после партии (`COSS3_KEEP_ALIVE`), и это удобно ровно до того, как отчёт
отправлен: дальше он просто занимает место. Признак в логе — строка
`отправлено: results/<дата>/<идея>/<копия>`. После неё контейнер не нужен: тома
`~/io-*` остаются на хосте, отчёт и трасса читаются с них напрямую.

```bash
# что уже отыграло и отправило результат
for c in $(docker ps --filter name=coss3- --format "{{.Names}}"); do
  docker logs "$c" 2>&1 | grep -q "^ *отправлено: results/" && echo "$c — отыграл, гасить"
done
```

Хочешь, чтобы контейнер гасил себя сам, — `-e COSS3_KEEP_ALIVE=0` при запуске.
Живым держат только тот, в который собираешься лезть `docker exec`.

**Проверено 15.09:** четыре контейнера простояли час после того, как отправили
результаты, — впустую.

## Для чего ферма НЕ годится

**Правку `.inc` здесь не проверяют.** Цикл одной проверки — три минуты ожидания
пульса, экрана не видно (он чёрный), а при поломке контейнер говорит «ПУЛЬСА
НЕТ», и причин у этого три. На Windows тот же вопрос закрывается за тридцать
секунд. Правило куплено 13.09 за полтора часа и четыре перезапуска.

Здесь проверяют ДРУГОЕ: идею на многих копиях при одинаковых условиях.

## Бот против бота — вывод только ПАРОЙ: прямая волна и зеркало

**Одиночная волна бот против бота не различает стратегию и сторону карты.**
Слоты на нашей карте неравны, и неравны сильно: замер `bot2_side_pol` (3.11) гнал
ОДИН И ТОТ ЖЕ файл на оба слота, и слот 0 дал размен 0,96–3,38 против 0,30–1,04
у слота 1 (медианы 1,64 и 0,61), а в крайней копии армию 866 против 1 и 185
убитых крестьян против 18. То есть сторона стоит двух-трёх раз по размену —
больше, чем любая разница стратегий, которую мы ловили за два дня.

**Поэтому идея, которую проверяют ботом против бота, ставится ДВУМЯ волнами:**

| волна | слот 0 | слот 1 |
|---|---|---|
| прямая `<идея>` | идея | контроль |
| зеркало `<идея>_mirror` | контроль | идея |

Вывод делается только по шести копиям сразу. Если размахи прямой и зеркала
накрывают друг друга — вывода НЕТ, как бы ни было красиво в одной волне.
Итог первой волны кладётся в `experiments.ini` с пометкой «читать только с
зеркалом», чтобы следующая сессия не прочитала половину за целое.

**Цена правила — три снятых вывода за два дня:** (142) мака, (165) и (169) мои.
Хуже всех (169): он был сделан до зеркала, которое я сам же в том разделе и
просил. Ярлыки сторон брать из `опыт.json` копии, а НЕ по имени файла — в
зеркале имя читается наоборот.

**И метку `verified` нельзя двигать, пока идёт пара.** Иначе зеркало сыграет на
другом мосту, и отличий между волнами станет два вместо одного.

## Шаг 0. СОБЫТИЯ ИДУТ ЛОКАЛЬНОЙ МОДЕЛИ — прогреть её до старта

Решение игрока 23.09: событийные вопросы уходят локальной модели ВСЕГДА. Это
прописано в окружении контейнеров (`~/coss3.env`), а не во флагах идеи:

    COSS3_EVENT_MODEL=qwen3:30b-a3b
    COSS3_EVENT_URL=http://10.41.2.77:11434/v1

**Перед КАЖДОЙ серией — прогреть, иначе первое событие платит загрузкой**
(16 ГБ, 34 с, и эти секунды попадают прямо в такт):

```bash
python найти_ollama.py                 # жив ли адрес; мак переезжает по DHCP
python warm_local.py --minutes 120     # умолчание — qwen3:30b-a3b
```

Мост идёт РОДНЫМ путём ollama (`/api/generate`), где схема работает
грамматикой: думающая модель там не думает вовсе — 1,9–2,9 с и 27 токенов
против 48–344 с через `/v1`. Ключ `--event-native 0` возвращает старый путь,
если надо сравниться с прежними плечами.

Три вещи, которые смотреть в логе прогона:

* `адрес событий — ollama, идём РОДНЫМ путём` — канал встал как задумано;
* `родного пути нет (...)` или `ВНИМАНИЕ: адрес событий ... НЕ отвечает` —
  события пойдут ОБЛАКОМ запасным путём, и с локальным плечом такой прогон
  сравнивать нельзя;
* `событие уходит в ЗАПАСНУЮ модель` — локальная отвалилась посреди партии.
  В трассе у события есть поле `model`: по нему видно, кто ответил на самом
  деле, и сколько событий ушло не тем путём.

**Базы, снятые до 23.09, снимались на ОБЛАЧНЫХ событиях** (`base26` в том
числе). Сравнивать с ними новые прогоны нельзя — базу снимать заново.

## Шаг 1. Контроль до старта

```bash
docker ps                                  # движок жив? после wsl --shutdown его надо поднять заново
cd ~/coss3-git && git log --oneline -1 verified
git show verified:docker/experiments.ini | grep -n "^\[<идея>\]"
```

**Идея должна быть в клоне ПО МЕТКЕ `verified`, а не на `master`.** Контейнер
читает `experiments.ini` из своего клона, и если идею завели на мастере, прогон
упадёт на «идея не взята» — намеренно, чтобы прогон без флагов не выглядел
законным и не попал в сравнение.

Если идея требует правки кода, а не флага — она живёт в ВЕТКЕ: `ref = имя_ветки`
в её секции. Пересобирать образ не нужно.

## Шаг 2. Поднять

Имя идеи и префикс пишутся **прямо в команде**. Переменных оболочки нет
нарочно: 14.09 серия отыграла пятнадцать минут впустую из-за того, что `IDEA`
была задана в одной оболочке, а `docker run` шёл из другой.

```bash
docker rm -f $(docker ps -aq --filter name=coss3-) 2>/dev/null
git -C ~/coss3-git pull          # entrypoint.sh монтируется отсюда

for n in 1 2 3; do
  rm -rf ~/io-s$n ~/profile-s$n
  mkdir -p ~/io-s$n ~/profile-s$n
  cp -a ~/profile/. ~/profile-s$n/
done

for n in 1 2 3; do
  docker run -d --name coss3-s$n --env-file ~/coss3.env --entrypoint /usr/bin/tini \
    -e COSS3_BRIDGE_GIT=git@github.com:snipstack-cloud/coss3-bridge.git \
    -e COSS3_BRIDGE_REF=verified \
    -e COSS3_EXPERIMENT=shooters \
    -e COSS3_RESULTS_NAME=shooters/$n \
    -e COSS3_RESULTS_GIT=git@github.com:snipstack-cloud/coss3-results.git \
    -e COSS3_RESULTS_KEY=/ssh/results_key \
    -v ~/io-s$n:/io -v ~/profile-s$n:/profile \
    -v ~/.ssh/coss3_deploy:/ssh/deploy_key:ro \
    -v ~/.ssh/coss3_results:/ssh/results_key:ro \
    -v ~/coss3-git/docker/entrypoint.sh:/opt/bridge/entrypoint.sh:ro \
    coss3:2 -- /bin/bash /opt/bridge/entrypoint.sh
done

docker logs -f coss3-s1
```

**Профиль копируется каждой копии свой.** Общий том игра портит, а пустой
означает, что она встанет на выборе профиля и до меню не дойдёт.

Число партий берётся из флагов идеи (`--episodes 3`). Нужна одна партия —
перебить окружением: `-e COSS3_EXTRA_FLAGS="... --episodes 1 ..."`; контейнер
скажет об этом строкой «флаги из окружения ПЕРЕБИВАЮТ файл идей». Горизонт
партии — 900 игровых секунд по умолчанию, это и есть «пятнадцать минут».

Первую партию заводить руками не нужно: контейнер сам шлёт `NEW` с условиями из
`COSS3_MATCH_*`.

## Шаг 3. Четыре строки лога — и только потом ждать

```
мост обновлён: <SHA>            та ли версия играет
идея «<имя>»: <описание>        идея прочитана из experiments.ini
  флаги: ... --hints-extra ...  чем идея отличается от базы
пульс есть: тик Progress жив    блоки скомпилировались
партия идёт: coss3_eco_P0.dat   человеческий игрок на месте
```

Нет строки «идея» — гасить сразу, не ждать пятнадцать минут: прогон проверяет
базу под именем идеи. Нет флагов — то же самое. Нет пульса через три минуты —
смотреть `game.log` в томе.

Проверить, что поле нового моста доехало:

```bash
docker exec coss3-s1 grep -o 'fighters = .\{0,140\}' /opt/cossacks/coss3_eco_P0.dat
```

Состояние и пульс лежат в каталоге ИГРЫ внутри контейнера (`/opt/cossacks`), а
трасса, логи и отчёт — в `/io`, то есть на томе и с хоста читаются напрямую.

## Шаг 3а. Проверка годности копии на 10-й минуте — три числа

Копия может отыграть партию до горизонта и быть НЕГОДНОЙ: 2.11 одна из четырнадцати шла вчетверо медленнее
остальных, её колония умерла от голода (крестьян 19 → 11, еда 0, погибло 13, армии ноль), и **враг в ней тоже
недоразвит** — 16 крестьян против 58 у сестры. То есть виноват не замер и не стратегия, а движок в этой копии.
Числа такой копии в сравнение не идут, а её голод легко принять за находку про хозяйство.

Признак проверен на всех 14 копиях того дня, разделение полное:

| что | здоровые (13) | негодная |
|---|---|---|
| темп, игровых секунд на реальную (поле `t_real` трассы) | **1,19–1,42** | **0,34** |
| крестьян на 10:00 | **56–59** | **11** |
| еда на 10:00 | 1117–3735 | **0** |

**Порог: темп ≥ 1,0, крестьян ≥ 45, еда > 0.** Нарушено любое — гасить копию, сохранить её том под отдельным
именем и поднять замену; в отчёте называть её негодной по построению, а не результатом.

```bash
# темп и здоровье по тому, не дожидаясь горизонта
python3 - <<'PY'
import json
def сек(s):
    ч,м,c=(str(s).split(":")+["0","0"])[:3]; return int(ч)*3600+int(м)*60+float(c)
строки=[json.loads(l) for l in open("/home/lapst/io-s1/coss3_bot.jsonl",encoding="utf-8") if l.strip()]
такты=[x for x in строки if "finish" not in x]
пары=[(сек(x["t_real"]),x["gt"]) for x in такты if x.get("t_real") and x.get("gt") is not None]
темп=(пары[-1][1]-пары[0][1])/(пары[-1][0]-пары[0][0])
снимок=[x["state"] for x in такты if (x.get("gt") or 0)<=600 and x.get("state")][-1]
print("темп %.2f | крестьян %s | еда %s" % (темп, снимок.get("peasants"), снимок.get("food")))
PY
```

**Чего в этот признак НЕ включать:** «погибло крестьян». У нидерландских 45-минуток погибло 21–23 — это боевые
потери, копии здоровы. Признак работает только тройкой, по отдельности каждое число обманывает.

**И следствие, которое дороже признака:** игровое время в медленной копии идёт, а игра — нет. На одной и той же
игровой секунде она отыграла втрое меньше, поэтому «замедление на сравнение не влияет, мост считает по игровым
секундам» — неверно. Сравнивать копии с разным темпом нельзя даже на одинаковых рубежах.

## Проверка моста в контейнере — ОДНА копия, и это НЕ замер

Отдельный порядок, короче серии. Нужен, когда мост изменился и надо убедиться,
что ферма его возьмёт и петля не упадёт. Одна копия, один эпизод, десять минут.

**Имя результата НЕ совпадает с именем идеи.** Флаги тут перебиты окружением,
сравнивать такую партию не с чем, и попасть в каталог идеи она не должна:
`COSS3_RESULTS_NAME=smoke<N>/1`. Перебивая флаги, повторить их ЦЕЛИКОМ — окружение
заменяет строку идеи, а не дополняет её.

```bash
rm -rf ~/io-sm1 ~/profile-sm1 && mkdir -p ~/io-sm1 ~/profile-sm1
cp -a ~/profile/. ~/profile-sm1/
docker run -d --name coss3-sm1 --env-file ~/coss3.env --entrypoint /usr/bin/tini \
  -e COSS3_BRIDGE_GIT=git@github.com:snipstack-cloud/coss3-bridge.git \
  -e COSS3_BRIDGE_REF=verified \
  -e COSS3_EXPERIMENT=base8 \
  -e COSS3_EXTRA_FLAGS="--memo --world /io/world.md --critic /io/разбор.md --episodes 1" \
  -e COSS3_RESULTS_NAME=smoke8/1 \
  -e COSS3_RESULTS_GIT=git@github.com:snipstack-cloud/coss3-results.git \
  -e COSS3_RESULTS_KEY=/ssh/results_key \
  -v ~/io-sm1:/io -v ~/profile-sm1:/profile \
  -v ~/.ssh/coss3_deploy:/ssh/deploy_key:ro \
  -v ~/.ssh/coss3_results:/ssh/results_key:ro \
  -v ~/coss3-git/docker/entrypoint.sh:/opt/bridge/entrypoint.sh:ro \
  coss3:2 -- /bin/bash /opt/bridge/entrypoint.sh
```

Смотреть по порядку, каждое следующее только после предыдущего:

| что | где | признак беды |
|---|---|---|
| та версия моста | `мост обновлён: <SHA>` | не тот SHA — метка не сдвинута или клон отстал |
| идея прочитана | `идея «имя»` | нет строки — прогон проверяет базу под чужим именем |
| блоки собрались | `пульс есть` + числа блоков в `install.log` | числа изменились, а `.inc` не трогали — ставится не то |
| партия пошла | `партия идёт: coss3_eco_P0.dat` | нет — смотреть `game.log` в томе |
| петля жива | `первый запрос ушёл на N игровой секунде` | трейсбек в логе — правка уронила политику |

**Числа блоков — самая дешёвая проверка того, что `.inc` не менялся.** Правка в
python их не двигает; сдвинулись — значит поставили не ту версию.

Дальше проверяется УЖЕ СВОЁ: то поле или та строка, ради которых всё делалось.
Трасса лежит на томе (`~/io-sm1/coss3_bot.jsonl`), состояние — внутри контейнера
(`/opt/cossacks/coss3_eco_P0.dat`). Ждать условие циклом, а не на глаз:

```bash
n=0; while [ "$n" -lt 100 ]; do
  grep -q "то_что_ждём" ~/io-sm1/coss3_bot.jsonl 2>/dev/null && { echo ДОЕХАЛО; break; }
  docker ps --format "{{.Names}}" | grep -q coss3-sm1 || { echo "контейнер погас"; break; }
  sleep 15; n=$((n+1))
done
```

Имена переменных в таком цикле — только латиницей: кириллическое имя bash
молча не примет, цикл выйдет сразу и скажет «ничего нет».

**Погасить, как только проверка ответила.** Досматривать эпизод незачем: партия
с перебитыми флагами в сравнение всё равно не пойдёт, а модель тратит токены.

**Чего проверка в контейнере НЕ заменяет.** Тик `Progress` проверяют на Windows
(см. «Для чего ферма НЕ годится»), а закажет ли модель то, ради чего правка
делалась, показывает СЕРИЯ, а не одна партия. Здесь отвечают только на вопрос
«мост доехал и петля жива».

## Переменные, которые решают

| | |
|---|---|
| `COSS3_BRIDGE_REF` | **`verified`**. `master` берут осознанно, контейнер об этом предупреждает |
| `COSS3_EXPERIMENT` | имя секции в `experiments.ini`; пусто — «одиночный прогон», сравнивать не с чем |
| `COSS3_RESULTS_NAME` | `<идея>/<копия>`; пустой сегмент отвергается до старта игры |
| `COSS3_EXTRA_FLAGS` | перебивает флаги идеи; аргументы разделяются пробелами, поэтому многословный текст передавать ФАЙЛОМ через `--hints-extra` |
| `COSS3_EPISODES` | партий подряд; флаги идеи её перебивают, они идут последними |
| `COSS3_MATCH_*` | условия партии: `RES`, `PEACE`, `AI`, `NATION`, `BALLOON`, `CANNONS`, `CAPTURE` |
| `COSS3_KEEP_ALIVE` | `0` — гасить контейнер после партии; по умолчанию держится живым |
| `COSS3_VNC` | `1` — экран на `localhost:5900`, если нужно смотреть глазами |

## Что в контейнере не работает и это нормально

**Чёрный экран.** Игра считает, но трёхмерную сцену не рисует — одинаково через
OpenGL и Vulkan, перепробовано всё вплоть до проброса видеокарты. Ферме это не
мешает: модель играет по файлам, партия начинается командой. Посмотреть, что на

## Завести новую идею

Секция в `docker/experiments.ini`, и она должна попасть под метку `verified`:

```ini
[имя]
что = одно предложение: что проверяем и откуда взялось, с числами
ref = verified
флаги = --memo --world /io/world.md --critic /io/разбор.md --episodes 3 --hints-extra /opt/bridge/hints_имя.txt
копий = 3
база = <с чем сравнивать>
```

**Отличие от базы — ровно одно.** Флаги идеи должны совпадать с флагами базы
плюс проверяемая строка, иначе в сравнении будет две разницы вместо одной.
**Мера называется ДО прогона** и пишется в поле `что`.
