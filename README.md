## Установка (Windows) — прежняя, компьютерная конструкция

    python install_bridge.py "C:\GOG Games\Cossacks 3"

Патчит `data\scripts\units\global.inc\progresseconomicai.inc`, делает бэкап
рядом с оригиналом. Идемпотентно. Обновить: `--reinstall`. Снять: `--uninstall`.

Скрипт откажется работать, если якоря в файле не найдены ровно один раз —
это значит, что версия игры отличается от 2.2.3.92.6008 и патч нужен вручную.

## Обновление уже установленного моста

    powershell -ExecutionPolicy Bypass -File .\fix.ps1

`fix.ps1` сам находит игру, снимает старую версию и ставит новую (`--reinstall`),
делая бэкап рядом с оригиналом. Игру перед этим закрыть. Вручную то же самое:

    python install_bridge.py "<путь к игре>" --reinstall --outdir "%USERPROFILE%\coss3-io"

Проверка после боя: рядом с `coss3_eco_P<n>.dat` должен появиться
`coss3_map_P<n>.dat`, а в состоянии — ключи `grid_n`, `brow0`, `en_armies`.

    python coss3_map.py "%USERPROFILE%\coss3-io" 1

печатает обстановку: три слоя мини-карты, залежи, угрозу, состав сторон.

## Протокол

    игра ->  <outdir>\coss3_eco_P<n>.dat   состояние, каждый тик ИИ
    игра ->  <outdir>\coss3_map_P<n>.dat   местность, не чаще раза в 20 игровых секунд
    игра <-  <outdir>\coss3_cmd_P<n>.dat   команды экономики; игра читает и УДАЛЯЕТ
    игра <-  <outdir>\coss3_atk_P<n>.dat   приказ атаки; читает блок ВОЕННОГО ИИ

Патчатся два файла: `progresseconomicai.inc` (состояние + импорт команд) и
`progresswarai.inc` (атака). Разделение вынужденное: состояния скриптов имеют
разные области видимости, `_ai_CreateAgressorArmy` из экономического не виден.

Файлы кладутся в КАТАЛОГ ИГРЫ (рядом с cossacks.exe) — движок резолвит
относительные пути туда.

Команды: BUILD(role, total), TRAIN(role, total), UPGRADE(name), SET_RES(res_id, pct).
BUILD и TRAIN декларативны — «хочу N штук всего», можно слать каждый тик.

`BUILD` принимает 14 ролей: `center`, `mill`, `ba17`, `ba18`, `stable`, `smith`,
`academi`, `market`, `house`, `minegold`, `mineiron`, `minecoal`, а с v2 ещё
`store` (7) и `tower` (13) — чтобы на увиденное на карте можно было ответить:
склад ближе к лесу, башни на опасной стороне. **Место выбирает игра**, не бот:
`_ai_TryUnit` только ставит идею, а `_ai_ProcessConstruction` сам ищет точку
рядом с базой. Заказать можно количество, но не направление.

## Что видно на карте (v2)

Мир режется на 16x16 клеток, колонка 0 — запад, строка 0 — север. Три слоя:

| слой | ключи | что показывает |
|------|-------|----------------|
| местность | `rrow{y}` (map-файл) | `#` густой лес, `+` редкий, `S` камень, `G`/`I`/`C` свободная залежь золота/железа/угля, `x` залежь занята шахтой |
| базы | `brow{y}` | `H` мой центр, `b` моё здание, `a` союзник, `e` враг |
| войска | `frow{y}` | цифра 1–9 — сила вражеской армии в клетке |

Плюс числом, в файле состояния: геометрия (`map_w`, `grid_n`, `my_cx/my_cy`,
`my_zone`), накопленная добыча `tot_*` (по её дельтам клиент считает реальную
скорость в минуту — `on_wood` показывает только приказы), залежи
(`ore_*_dist`, `ore_*_near`), угроза (`en_armies`, `en_force_total`,
`en_near_*`, четыре сильнейшие армии `a0_…a3_`, `danger_home`,
`last_attack_ago`), свои войска (`my_objects`, `mil_inf`, `mil_cav`, …),
таблица игроков (`p{n}_team/ai/enemy/objects/bldgs`).

В map-файле: `wood_slots_near/free`, `stone_slots_near/free`, `wood_dist_cells`,
`ore_free_*` и до восьми ближайших свободных залежей `o{k}_res/dist/cx/cy`.

Источники — те же структуры, что использует штатный ИИ: `TEnemyInfo.armyInfos`,
`TTopZone.danger/attract`, `aidata.orelist`, `gResGrid`, `stat.restotal`,
`gPlayer[].lists.buildings`.

Готовый рендер для промпта модели:

    from coss3_bridge import Bridge
    from coss3_map import render
    br = Bridge(save_dir, plind=1)
    prev = None
    while True:
        s = br.wait_state()
        print(render(s, br.read_map(), prev))
        prev = s

## Использование

    from coss3_bridge import Bridge, build, train, upgrade

    br = Bridge(save_dir, plind=1)
    while True:
        s = br.wait_state()
        if s["centers"] < 2:
            br.send([build("center", 2)])
            br.wait_consumed()

## Отправить цель руками

    python send.py store=3 tower=2          # держит цель, пока не выполнится
    python send.py center=4 ba17=6 --ticks 60
    python send.py train:peasant=40
    python send.py upg:food140
    python send.py store=3 --once           # один раз, без удержания
    python send.py --attack 12              # волна из 12 бойцов в атаку

Каталог по умолчанию `~/coss3-io`, ИИ-слот ищется сам по `bai=True`
(переопределяется `--dir` и `--plind`). Запускать во время боя.

## Разработка без игры

    python mock_game.py ./sandbox --speed 25 --tick 1

Мок повторяет поведение вставки: те же 37 полей в том же порядке, читает
и УДАЛЯЕТ файл команд, печатает 'bridge: applied N commands for P<n>'.
Экономика упрощённая, но живая — крестьяне добывают, стройка занимает слоты,
апгрейды стоят ресурсов. Позволяет отладить бота до того, как появится игра.

Флаги: --plind, --tick (интервал тика ИИ), --speed (ускорение), --slots.

## Что снять при первом запуске

1. `save_dir` — найти `coss3_eco_P*.dat` поиском по диску
2. Формат .dat — сверить с догадкой (`<name> : section.begin / key = value / section.end`)
3. `gc_resource_type_*` — значения для SET_RES, снять логом

Мост активен ТОЛЬКО для ИИ-игроков (`if (bai)` во вставке): бот должен быть
компьютерным оппонентом. Номер в имени файла = plind, сверьте с полем `plind`
внутри состояния.

**Именно эта строка и сделала переезд неизбежным:** правила хакатона требуют
человеческого слота, а здесь мост работает только на компьютерном. На
человеческом слоте всё наоборот — блок висит на якоре
`progresstick := progresstick+1`, который выполняется для КАЖДОГО игрока, тогда
как `ExecuteState('ProgressAI')` строкой выше — только для `bai` или человека с
включённым советником. Разбор — `HANDOFF.md` §7a.
