# Симулятор Cossacks 3: что делаем и как

Точка входа — **`~/coss3-bridge/sim/СПЕЦИФИКАЦИЯ.md`**: §0–10 замысел и
механики, §11 сборка и её три захода, §12–13 обучение (13а–13м — дневник
находок). Состояние дел и переписка с Windows — `~/coss3-bridge/ПЛАН.md`
(состояние, не журнал: сделанное удаляется), причины правок — `WORKLOG.md`.
Скиллы рядом: `coss3-human-bot` (мост, правки `.inc`), `coss3-results`
(разбор записей), `coss3-start`/`coss3-stop`.

## Зачем это всё

Живая партия стоит 16–20 минут и около 0,45 доллара облачной модели; денег на
серии мало (три копии — наблюдение, не измерение). Симулятор гоняет партию за
0,1–0,5 с без сети и нужен для трёх вещей: искать стратегию, которую потом
проверит живая серия; калибровать механики по записям; учить сеть-политику
там, где правило в питоне не пишется руками. **Он не заменяет живую игру:
всякая находка симулятора — гипотеза до серии на Windows.**

## Правила, из которых следует всё

1. **Числа механик — из кода игры и из записей, никогда из памяти модели.**
   Каждое число в `sim/` несёт метку `[код]` (строка скрипта игры), `[замер]`
   (по записям, с числом записей) или `[допущение]` (в §10). Локальная модель
   (`sim_params_llm.py`) только вытаскивает числа из текста скриптов, и каждое
   сверяется регуляркой; расхождение — в `параметры.json` как «модель!».
2. **Сначала ворота, потом сборка, потом обучение.** Ворота — сверка одного
   слоя (экономика, движение, бой) с записями по названным до счёта мерам.
   Замкнутый цикл — команды записи проигрываются в симуляторе против той же
   записи. Обучение — только на симуляторе, прошедшем оба.
3. **Мера называется до прогона.** Что считаем и какое число ждём — записано в
   спецификации или в `docker/experiments.ini` до того, как запущен счёт.
4. **Ложный ноль проверять первым.** Прежде чем сказать «этого не было»,
   убедиться, что поле пишется в трассу и в каком виде (правило `coss3-results`
   §3а). Здесь оно срабатывало: `upg_done` в последнем такте пуст — брать
   последний такт с полями; `brow` — легенда букв, не числа.
5. **Считать по свежим записям.** Архив 2026-09-22..26 в `~/coss3-res`
   (`<дата>/<идея>/<копия>/`), 66 записей на 27.09; всё до 22.09 без частого
   снимка `coss3_snap.jsonl` в симулятор не идёт.
6. **Отрицательный результат записывается числами** в спецификацию, как и
   положительный (13г, 13з — примеры).

## Устройство, файл за файлом

| файл | что |
|---|---|
| `sim/core.py` | экономика на такт: добыча по балансовым темпам из записей, стройка с удорожанием (`costpercent`, сверено 121/121), найм по очередям (очереди одного здания делят его темп), апгрейды по ценам записи, порог еды 500 |
| `sim/sim.py` | сборка: `Запись` (трасса + снимки; `en_base` по «e» в `brow`; потолок «+» 36 или 62 по наличию `cells`), `Симулятор.такт()` (стройки → найм → движение групп → бой на клетку → крестьяне → исход), `команда()` (словарь моста), `состояние()` (словарь моста наружу), `партия(каталог, политика)` |
| `sim/combat.py` | закон потерь: `k·бьющих·урон/hp`, k 0,317, все бьют (`ДОЛЯ_ИЗЛИШКА` 1,0), урон не меньше ¼ атаки поверх формулы кода, шум `2^N(0, 1,33)` |
| `combat_math.py` (корень) | формула урона игры: атака минус защита по типу, не меньше 1 (`miscext2.script:434`); поправка на строй врага; **общая с мостом, порог урона в неё не вносить** |
| `sim/gate.py`, `gate_move.py`, `gate_combat.py` | ворота экономики, движения, боя |
| `sim/replay.py` | замкнутый цикл по записям: `прогнать(каталог, seed)`; партии яруса 1 без дебюта в `cmds` узнаёт по ратуше в первом такте и проигрывает `debut.Дебют(20)` |
| `sim/goals.py` | лестница целей (9 ступеней, одни поля для записи и симулятора), `курс`, `доля_у_крестьян` |
| `sim/tier1.py` | ярус 1: хозяйство скриптом, как `--tier1` моста |
| `sim/policy_net.py` | полный словарь: 53 действия раз в 15 с, сеть 64 скрытых |
| `sim/policy_strat.py` | стратег: 15 решений раз в 60 с поверх яруса 1 |
| `sim/train.py` | эволюция CEM: `--strat --ladder --gens --pop --k --seed --out`, `--eval` |
| `sim/ladder_eval.py` | доли взятых ступеней на отложенных партиях: запись, ярус 1, сети |
| `sim/sweep_army.py` | перебор скриптованных планов (`План`) на всех записях |
| `sim/параметры.json`, `темпы.json`, `параметры_юнитов.json` | числа механик с источниками |
| `sim/ночь/` | ночные сети и `ИТОГ.md` |

Враг в симуляторе — **запись**: его сетки (`frow`, `prow`), армия и крестьяне
берутся из той партии, с поправкой на наши убийства сверх записи (§5). Отсюда
предел: выманить его армию, спровоцировать его волну, изменить его найм
симулятор не умеет. Планы, которые меняют поведение врага, им не проверяются.

## Числа механик: как добывать и проверять

* Скрипты игры лежат в `<игра>/data/scripts`; `grep -r` на macOS молчит —
  искать `os.walk` + `latin-1` + подстрока (см. `coss3-human-bot` шаг 2).
* Читать объявление целиком, а не позицию аргумента: `120` в `SetObjBaseWeapon`
  оказалось паузой перезарядки, не дальностью.
* Проверенные места: цены и `costpercent` — `unit.script:493/503`; урон —
  `lib/miscext2.script:276-440` (`_misc_DoDamage`); предпосылки построек —
  `lib/country.script:2926-2944` (`_country_AddFixedProduceWithAccessControl`,
  `req0`: мельница и шахты без предпосылок, кузница/склад/дом — ратуша,
  казарма/конюшня — кузница, академия — казарма); строй — `formations.cfg` и
  `miscext2.script:351-353, 428-431`; скорость игры — `progress/progress.inc/nothing.inc:507-627`.
* Темпы (добыча, найм, скорость марша, растяжение волны) — только по записям,
  `sim_rates.py` → `темпы.json`; балансовые темпы главнее пошаговых.
* Что кодом не проверить — спросить игрока (память `coss3-mechanics-from-player`),
  ответ хранить с меткой `[игрок]`.

## Проверка симулятора: порядок и достигнутые числа

Порядок всегда один: ворота слоя → замкнутый цикл → разложение остатка по
месту (у нас ≤ 5 кл / в поле / у него ≤ 3 кл), по фазе (до 600 / 600–900 /
после 900 с), по соотношению сил и по эпизодам. Мера боя — `|log2(пред/факт)|`
по сторонам, доля в пределах двух раз, размен (его потери на нашу).

Состояние на 27.09 по 66 записям, замкнутый цикл (сим / факт):

| мера | сим | факт |
|---|---|---|
| наши потери, сумма | 13 374 | 10 210 (смещение +0,25, |log2| 0,54) |
| его потери, сумма | 4 639 | 4 800 (смещение −0,14, |log2| 0,75) |
| убитых крестьян, сумма | 1 504 | 1 541 (медиана смещения −0,73) |
| размен у нас / в поле / у него | 0,38 / 0,28 / 0,37 | 0,67 / 0,46 / 0,40 |
| побед по правилу §7 | 4 | 0 |

**Открытые перекосы, помнить при выводах:**
* **наши потери в сумме на треть выше записи** (+0,25): враг с 27.09 восполняет
  потери наймом (§13м) и держит нас в бою дольше, чем живая партия, где модель
  отводила армию. Медиана ошибки при этом лучше прежней (0,54 против 0,59);
* убитых крестьян недобор (−0,73): его бойцы связывают наших, потому что армия
  больше не выбивается насовсем;
* размен у нас 0,38 против 0,67 в записи: оборона целой армией воспроизводится
  законом (194 против 36 дают 2,7), но в замкнутом цикле команды записи уводят
  армию к его базе раньше его прихода;
* своей механики ОТХОДА у врага нет: его уход из клетки берётся из сетки
  записи (в жизни из клетки уходит 90 % исчезнувших, гибнет 10 %);
* поля истощаются к концу партии (`food_ready` 0–5), действие SEED на
  выкошенное поле неизвестно.

**ЗАКРЫТО 27.09 (§13м), не искать заново:** «массовый удар по его базе в
симуляторе выигрывает». Причина была не в законе боя (он верен: размен растёт с
перевесом — 0,32 / 0,69 / 1,04 по точным клеткам `strike_base`), а в том, что
симулятор вычитал наши убийства из его армии НАВСЕГДА. Враг нанимает 19,7
бойца в минуту, и ни в одной из 66 записей его армия в конце не меньше
начальной. Теперь «убитые сверх записи» залечиваются фактическим наймом из
записи (`Симулятор.найм_врага`): побед 14 → 4, полный словарь 22 из 48 → 3.
Отвергнуты: множитель атакующему по месту, потолок фронта у его базы
(`combat.ФРОНТ_У_ЕГО_БАЗЫ`, оставлен выключателем со значением None), снятие
порога урона.

Что делать, когда придут записи с новым мостом (потолок сетки A–Z и точные
`cells` с 26.09): ворота боя возьмут точные клетки сами; первым делом пересчитать
бой при 100+ в клетке и перекос у его базы.

## Что учить и как

**Зачем два словаря.** Полный словарь (`policy_net`, 53 действия) до 26.09
не учился ничему: награда плоская. Поэтому хозяйство отдано ярусу 1, а сети —
стратег: 15 крупных решений раз в 60 с (удар всей армией / 30 по крестьянам,
базе, армии; апгрейд атаки/защиты; вторая казарма; мушкетёры; отход;
присутствие с досылкой; присутствие у крестьян без его бойцов). Каждое
решение добавлялось только когда меняло исход. 27.09 полный словарь впервые
выучился — значит, как только дыра у его базы закрыта, учить надо его.

**Предохранитель `train.ПОТОЛОК_СТУПЕНИ`** (9 = выключен): ограничивает верхнюю
ступень в награде, если снова найдётся дыра, к которой тянется сеть.

**Награда — лестница** (`--ladder`, `goals.py`): число взятых ступеней +
половина пути к ближайшей невзятой + 1,5·присутствие у крестьян (до 0,4) −
0,002 за потерянного бойца, но только когда присутствие ≥ 5 % — иначе сеть
учится не воевать (это было, 25.09). Ступени 5 и 7 запись даёт «подарком»
(его армия и крестьяне тают сами) — сравнивать с «только ярус 1», а не с нулём.

**Как гонять:**

```bash
python3 sim/train.py /Users/gs/coss3-res --strat --ladder --gens 300 --pop 48 --k 6 --seed 2 --out sim/ночь/имя.npy
python3 sim/ladder_eval.py /Users/gs/coss3-res --net sim/ночь/имя.npy --seeds 3
python3 sim/sweep_army.py /Users/gs/coss3-res --sweep2      # перебор планов без обучения
```

Правила обучения, купленные прогонами:
* один прогон с одним зерном — наблюдение; результат — когда 3–4 зерна
  сходятся по исходу (27.09 сошлись по исходу, разойдясь по решениям);
* `--k 6` (партий на кандидата) вместо 3 — награда шумит вдвое меньше;
* 80 поколений — 15 минут, 300 — 2,5 часа; шесть прогонов параллельно на M4
  идут без потери темпа; ночью запускать через `nohup`, утром `ИТОГ.md`;
* отложенные партии фиксированы (`train.разбить`, seed 7): 16 из 64;
  смотреть на них, не на обучение;
* перебор планов (`sweep_army.py`) дешевле обучения и отвечает по каждому
  параметру отдельно — начинать с него, обучать, когда план не пишется руками;
* перед выводом «сеть нашла стратегию» проверить, не нашла ли она дыру: сколько
  побед по §7 (в записях их НОЛЬ — много побед значит дыру), где бои, сходится
  ли с живой записью такого же плана. Так поймана §13л.

## Перенос в игру

Цепочка: симулятор → стратегия в 2–4 правила → подсказка `hints_<идея>.txt`
(тег `[война]`, команды моста буквально в JSON) → секция `[идея]` в
`docker/experiments.ini` с мерами ДО прогона, механической мерой «идея
доехала» и «чего не ждать» → задание Windows в `ПЛАН.md` (три копии, база —
ближайшая по замыслу серия, не обязательно base28) → разбор по `coss3-results`
→ подтверждённое в `hints_human.txt`.

Что уже прошло этот путь: `strike_late` (25.09, ждёт денег), `no_gather`
(сыграна: 95 убитых против 3 у базы — лучшее в проекте), `home_defense`
(задание симулятора: размен дома 2,93 — дал закон фронта), `free_peasants`
(27.09, запущена Windows), `strike_base` (27.09, запись ради чисел — закрыла §13м). Правило постановки от Windows: **срок модель держит,
бессрочный запрет — нет**; в подсказке писать «до 10:00», а не «никогда».

Обратная сторона той же цепочки: живая серия → новые записи в `~/coss3-res`
(`git pull`) → `replay.py` и ворота на них → правка ядра → снова обучение.
Задания Windows можно ставить и ради данных для симулятора, не ради цели
(`home_defense` так и был поставлен), — это самый дешёвый способ добыть
недостающую механику.

## Ловушки, каждая стоила прогона

* среднее по 168 трассам — история моста, не механика (память `coss3-corpus-era`);
* растяжение волны в бою резало и без того мелкие группы — введено по замеру,
  снято по замкнутому циклу (§11); измерять эффект правки по всем записям,
  а не по одной;
* бой на группу вместо клетки: пять групп по три в одном окне каждая принимала
  удар всего фронта;
* отказ «не хватает» без повтора: симулятор покупал 2 апгрейда из 3, где модель
  в записи повторяет команду; теперь заказ ждёт в очереди;
* закладка без свободных рабочих отбрасывалась — партия без казармы;
* `p1_pea_lost`/`my_mil_lost` в снимке — накопительные с начала файла, брать
  разность с первым снимком партии (`rec_pea0`, `rec_kills0`);
* `«+»` в сетке сменил смысл 26.09 (36 → 62) — по знаку не отличить, смотреть
  `cells` или дату;
* вылазка домашней армии навстречу врагу вредит (13д): праздная армия в игре
  сама не выходит, только по приказу.
