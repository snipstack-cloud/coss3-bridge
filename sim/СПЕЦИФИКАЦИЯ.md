# Симулятор партии Cossacks 3 — спецификация (шаг 1)

Составлено 25.09.2026 по решению игрока строить симулятор и учить в нём
политику. Это документ для сборки, не замысел: у каждого правила указано, откуда
число (`sim/параметры.json`, `sim/темпы.json`, `world.md` с меткой, или «нет —
ворота покажут»). Что здесь не написано, в симуляторе быть не должно.

## 0. Что симулируется и что нет

Симулируется одна партия против нативного ИИ на открытой карте, в тех же
условиях, что играет мост (`match.dat`: nat 13 = net, ai1 = 3, res 0, peace 0,
capture 3, рынок и XVIII век запрещены). Горизонт 20 игровых минут. Уровень
детализации — агрегаты: числа ресурсов, крестьяне по занятиям, здания с
очередями, армия по видам, положение групп по клеткам 16×16. Нет пикселей,
путей обхода, отдельных юнитов и анимаций.

Не симулируется, а **воспроизводится из трасс**: враг. Его экономика, найм,
апгрейды и походы берутся записанным таймлайном одной настоящей партии (§5).
Симулятор отвечает только за наши решения и за столкновения.

## 1. Время

* Такт симулятора `dt = 5` игровых секунд — шаг частого снимка `coss3_snap.jsonl`,
  на котором посчитаны все темпы; сравнение с трассой идёт по тем же точкам.
* Решение политики раз в 3 такта (15 с) — темп такта моста в трассах (медиана
  между записями `coss3_bot.jsonl` 15–20 с).
* Партия: 240 тактов (20 минут). Конец раньше — по условиям победы или
  поражения (§7).

## 2. Состояние — тот же словарь, что отдаёт мост

Симулятор держит состояние в виде словаря с ключами `coss3_eco_P0.dat`,
чтобы политика, выученная в нём, читала живую игру без перевода, а
`llm_policy.situation()` и `validate_combat.py` работали на нём без правок.
Обязательные ключи (остальные из `block_hstate.inc` добавляются по мере
нужды и всегда под тем же именем):

| группа | ключи |
|---|---|
| время | `gametime` |
| ресурсы | `food wood stone gold iron coal` |
| крестьяне | `peasants idle_pea on_food on_wood on_stone on_gold on_iron on_coal on_build on_mine` |
| здания | `centers mills smiths ba17 stables academi my_stores houses mines_gold mines_iron mines_coal building_now wip` |
| очереди | `train_now ba_queues` |
| армия | `mil_inf mil_shooters mil_cav my_officers my_drummers my_freewar mil_hurt mil_away mil_near mil_far` |
| строй | `squads squad_units squad_form squad_dmg squad_def squad_hdmg squad_hdef` |
| потери | `my_pea_lost my_mil_lost` |
| еда | `my_farm my_farmused famine food_ready` |
| апгрейды | `upg_done upg_avail` |
| бойцы в числах | `fighters` — строка `infantry17=pikeman,hp90,atk8,...` из `параметры.json` с учётом взятых апгрейдов |
| карта | `grid_n my_cx my_cy arow0..15 frow0..15 prow0..15 brow0..15 drow0..15 my_army_cx my_army_cy my_army_n wave_cx wave_cy wave_n` |
| враг | все `p1_*`, которые есть в трассе на этом такте (§5), плюс `p1_squads_form` и бонусы строя |

Внутренние сущности симулятора (не видны политике, видны отладке):

```
Крестьяне:   по занятиям {food, wood, stone, gold, iron, coal, build, idle}, плюс
             шахтёры внутри шахт по каждой шахте (не больше 5, параметры.json
             gol/iro/coa: peasantabsorber 5; world.md [замер] «ровно пять»)
Здания:      список {sid, готово_на (0..1), строителей, очередь: [(sid, сколько или inf)],
             клетка}; удорожание следующего того же вида — costpercent из параметры.json
Отряды:      группы бойцов {вид → число, hp_средний, клетка, цель, режим
             (дом/сбор/марш/удар/отход), строй: bool, hold: bool, hurt}
Апгрейды:    множество взятых; эффект — прибавка к atk/dpike/dsword/dbullet/pause
             видов (bar.pikeman.1.N → атака пики, .2.N → защита; academy aca.N —
             урон пули %, перезарядка пули %; таблица эффектов — world.md [код] и
             upg_shown/upg_aca в трассах с ценами)
```

## 3. Экономика, правило на такт

Все темпы — `sim/темпы.json`, блок «балансовые» (ворота 25.09: пошаговые
медианы завышали дерево и камень вдвое, а железо занижали вдвое, потому что не
знали о 20 железа за пикинёра). Баланс партии по 52 партиям 22–24.09, на одного
занятого в игровую секунду:

| ресурс | темп/с | кв1–кв3 | примечание |
|---|---|---|---|
| food | 1,94 | — | ВАЛОВЫЙ, при расходе 0,046 на голову; подгонка плохая, см. §10 |
| wood | 1,04 | 0,91–1,26 | |
| stone | 1,22 | 1,11–1,38 | |
| gold | 1,65 | 1,63–1,67 | только шахтёры внутри золотой шахты |
| iron | 1,68 | 1,66–1,78 | только внутри железной |
| coal | 1,67 | 1,15–1,67 | только внутри угольной |

Правила:

1. `res[r] += темп[r] * занятых[r] * dt` для наземных; для шахт — по шахтёрам
   внутри, не больше 5 на шахту.
2. Еда (ворота 25.09, «поля»): расход `0,10 * (крестьяне + бойцы) * dt` всегда
   ([замер] 1311 шагов без добытчиков, кв1–кв3 0,093–0,105); валовый темп на
   крестьянина **1,92/с** до апгрейда мельницы и **×2,4** после `mil.1`
   ([код] `country.script:3454`, effectfood 140; [замер] по 13 партиям ×2,18).
   Пошаговая регрессия темпа (1,2) была занижена вдвое: она выбрасывала шаги с
   наймом, а при бесконечной очереди это почти все шаги с едой выше 500.
3. Порог еды: при `food < 500` найм и стройка встают (`world.md` [код], 500),
   `famine` при `food <= 0` (`world.md` [код], `bfamine`).
4. Поля: первое поле созревает через **~87 с** после мельницы ([замер] 52
   партии), до этого крестьяне на еде не приносят ничего; готовых участков
   (`food_ready`, максимум 32) в 52 партиях **ни разу не было нуля** при людях
   на еде — SEED успевал, и истощение поля в горизонте 20 минут не проявлялось.
   В ядре: еда идёт при `food_ready > 0`; динамика `food_ready` от посева не
   моделируется (в трассах она статична, Δ медиана 0). Открытым остаётся только
   поведение при отказе от SEED — в данных его нет.
4а. Доставка: добыча зачитывается через **20 с** после работы ([замер]: ресурс
   растёт скачками через 30–40 с после назначения; 20 с дают лучшую сумму ошибок
   ворот, 40 с ломают золото).
5. Стройка: заказ ставит здание с `готово_на = 0`; прирост за такт
   `строителей * dt / buildtime_s` (buildtime_s — параметры.json; для казармы
   93,75 с одним строителем; **число строителей делит время линейно — допущение,
   ворота проверят по `building_now`/`wip` трасс**). Цена списывается при заказе
   с удорожанием: `цена * (costpercent/100)^(уже_есть)`; так в трассах
   (`build_cost`) вторая казарма 2500 при первой 500.
6. Найм: очередь здания; выпуск `12,0/мин` на казарму пехоты (баланс, кв1–кв3
   10,8–12,3), `4,4/мин` крестьян на ратушу; стрелки и конница — темп по
   трассам не снят, **взять тот же 10,9 и пометить**. Цена юнита списывается при
   выпуске (`параметры.json`: пикинёр 25/0/0/3/20/0, мушкетёр net 50/0/0/8/4/0,
   крестьянин 100 еды). Число в `buildtime` юнитов НЕ время найма (45 с против
   5,5 по трассам) — не использовать.
7. Жильё: `my_farm` растёт с домами и ратушей (параметры.json: farm у зданий —
   поле есть у модели, сверить), найм крестьян стоит при `my_farmused >= my_farm`.

## 4. Карта и движение

* Сетка `grid_n = 16`, клетка 16 единиц при карте 256 (`coss3_map.py`).
* Наша ратуша и его база — из той же трассы, что и враг (§5): `my_cx/my_cy`,
  `en_base`. Расстояние между базами в трассах около 210 единиц (`mil_far`).
* Скорость марша 1,1 ед/с (`темпы.json`, [замер] 136 единиц за 122 с); конница
  56/32 от пехоты по константам движка (`параметры.json`: gc_obj_speed_*),
  крестьянин 40/32 — по коду, живой игрой не мерено.
* Группа движется по прямой между центрами клеток; путь — расстояние/скорость.
  Растянутость волны (хвост 22 единицы впятером, `world.md` [замер]) — в
  агрегатах как задержка прибытия части группы: половина приходит в срок,
  остальные линейно в течение `0,2 * путь / скорость`. **Допущение, ворота.**
* Клетки ресурсов и залежей: из `brow`/`prow`/`ore_*` трассы, для наших
  крестьян считается только «есть ли залежь в радиусе 40» — как в мосте.

## 5. Враг — записанная партия

Симулятор загружает одну трассу (`coss3_bot.jsonl` + `coss3_snap.jsonl`) и на
каждом такте выставляет `p1_*` из ближайшего по времени снимка/такта: армия по
видам, крестьяне, здания, ресурсы, `p1_fighters` (характеристики с апгрейдами),
`p1_squads_form` и бонусы строя, сетки `frow`/`prow`/`drow`/`brow`, походы
`en_march` (куда, сколько, за сколько секунд).

Две поправки, без которых это не противник, а кино:

1. **Его потери от наших ударов** уменьшают его армию относительно записи:
   `p1_армия_сим = p1_армия_запись − (наши_убийства_сим − наши_убийства_запись)`,
   не ниже нуля; то же для крестьян снаружи. Найм его продолжается по записи.
2. **Его походы** идут по записи (`drow`, `en_march`), но если наша армия в
   симуляторе стоит не там, где в записи, столкновение случается там, где
   встретились клетки, а не где в записи.

Ограничение честное: враг не реагирует на то, чего в записи не было (наш
ранний удар в него не заставит его строить башню). Это цена отказа от модели
ИИ; компенсация — обучать на **многих** записанных партиях (52 сейчас, растёт
с каждой серией), выбирая случайную на эпизод.

## 6. Бой

Столкновение — когда наша группа и его бойцы в одной клетке (как
`coss3_map.бой_по_клеткам`). Разрешение за такт:

1. Урон по формуле игры: `combat_math.урон` (атака минус защита по типу оружия,
   не меньше 1), характеристики обеих сторон с апгрейдами.
2. **Строй врага**: `combat_math.поправка_на_строй` по `p1_squads_form` /
   `_hold` и бонусам из записи; без полей — умолчание +2/+2 (замер 24.09: сводит
   смещение калькулятора с −1,44 до −0,14 log2). Наш строй — по нашему `squads`.
3. Закон потерь за такт — **качество**, не численность: замер по 329 боям
   показал, что отношение потерь не зависит от численного перевеса
   (`validate_combat.py`: K_факт 0,22 при перевесе и 0,7, и 2+). Поэтому за такт
   гибнет `ставка_потерь * dt` с каждой стороны, где отношение сторон задано
   качеством, а абсолют — по медиане потерь в контактах трасс (снять при
   воротах: потерь в секунду на контакт).
4. Шум: множитель потерь `2^N(0, σ)` с σ = 1,26 в log2 (медиана |ошибки| после
   поправки на строй). Без шума политика переобучится на детерминизм, которого
   в игре нет.
5. Стрелки: залпы до контакта — `combat_math.залпы_форы` по `rmax` и скорости.
6. Крестьяне врага в клетке нашей группы гибнут с темпом, снятым по трассам
   (веха «убит хотя бы один» — по `p1_pea_lost`); крестьянин убегает, пикинёр не
   догоняет (`world.md`) — коэффициент догона < 1, снять при воротах.
7. Дома лучше, чем в поле: у своей базы калькулятор без поправки сходится
   (+0,03), в поле и у него — −1,4: поправка на строй объясняет это целиком,
   отдельного «бонуса дома» не вводить.

## 7. Действия и исходы

Действия — команды моста, дословно те, что читает `llm_policy.to_commands`:
`BUILD role total`, `TRAIN role total|-1`, `BALANCE role total`, `BUILDERS cap`,
`SEED n`, `UPGRADE name`, `ATTACK count target [cx cy via hold_if_outnumbered
expires who]`, `MOVE count target`, `RETREAT`, `STAGE cx cy keep`, `FORMATION`.
Роли и цели — `coss3_bridge.ROLE`, `ПОЛИТИКА["цели_ATTACK"]`. Симулятор
отвергает команду по тем же причинам и теми же словами, что блок (`why` в
квитанции): нет здания, не хватает ресурсов, нет свободных, нет офицера или
барабанщика. Для обучения маленькой сети словарь действий кодируется
фиксированно: команда × роль × квант числа (1, 5, 20, all).

Исход партии — новая цель (`ПЛАН.md`): в одном снимке с 7:00 и 30 секунд подряд
армия врага < 10, крестьян снаружи < 10, наших у его базы > 50. Поражение —
ноль наших крестьян и бойцов, либо горизонт. Награда: +1 победа, формирующие
слагаемые — убитые крестьяне врага, свои потери с минусом, цель по армии.
Веса слагаемых — параметры обучения, не спецификации.

## 8. Ворота (шаг 3) — интерфейс

`sim/gate.py <каталог прогона>`: берёт трассу, подаёт в симулятор её команды
(`cmds` тактов) в те же моменты, врагом ставит её же запись, и печатает по
первым 600 с расхождение кривых `food wood stone gold iron coal peasants
mil_inf` (медиана |сим − трасса| / трасса), время первой волны, потери в каждом
контакте против `my_mil_lost`/`p1_mil_lost`. Порог — 15 % за первые 10 минут;
не прошёл — в спецификацию добавляется механика, а не подгоняется константа.
Все допущения, помеченные в §3–§6, проверяются здесь и получают метку [замер]
или снимаются.

## 9. Пропускная способность

Цель — 1000 партий в час на M4: 240 тактов × 1000 = 240 тысяч тактов в час,
67 в секунду, на такт около 15 мс в чистом питоне — достижимо на агрегатах без
пикселей. Партии считать пачкой (numpy по оси партий) — тогда и 10 тысяч в час.
Без языковой модели в цикле: политика — таблица или маленькая сеть.

## 10. Открытые допущения, единым списком

1. Расход еды при добытчиках: вычитать или нет (§3.2).
2. Истощение поля и k выкашивания (§3.4).
3. Время стройки от числа строителей (§3.5) — линейно ли.
4. Темп найма стрелков и конницы (§3.6) — как у пехоты?
5. Растянутость волны как задержка (§4).
6. Абсолют потерь за секунду контакта и коэффициент догона крестьян (§6).
7. Время стройки зданий по формуле движка (академия 625 с) — не проверено ни
   для одной постройки; в трассах есть `building_now`/`wip` — сверить.

Каждый пункт закрывается воротами по трассам, не мнением.

Третий заход (25.09, «розыгрыш»): проверено, ОТ ЧЕГО ранняя ошибка дерева и

малых запасах; порог 15 % относительной ошибки на ранних малых запасах не
применим, честная мера там — абсолютная ошибка не больше одной доставки.**

51 вектор в `параметры.json`): между партиями темпы различаются в 1,5 раза по

### Ворота боя (25.09, `sim/gate_combat.py`, ядро `sim/combat.py`, 329 боёв)

Закон ядра: потери стороны за секунду = k × бьющих чужих × урон чужого за удар
(с поправкой на строй) / здоровье своего; бьющих = min(сторон в клетках боя) +
половина излишка большей стороны; при насыщении клетки («+») число в клетке
берётся как есть — нижняя граница 36, а не вся армия. k = 0,315 ударов/с на
бойца (подгонка под нулевое смещение), шум 2^N(0; 1,33) на потери каждой стороны.

| набор | n сторон | смещение log2 | медиана \|log2\| | в 2 раза | знак верен |
|---|---|---|---|---|---|
| все эпизоды | 658 | ≈0 | 0,82 | 59 % | 84 % |
| без насыщения клетки | 306 | −0,26 | 0,82 | — | — |
| с насыщением («+») | 352 | +0,28 | 0,82 | — | — |

Что проверено этим: (1) закон «каждый бьёт всей армией» отвергнут — при
насыщении он завышает потери втрое (+1,61); (2) чистый min сторон хуже блэнда
(0,90 против 0,82); (3) остаток по масштабу боя ±0,27 log2 — квантование «36 и
больше», снять его можно только числом в клетке без потолка (`block_hstate`,
знак «+»). Разброс σ 1,33 идёт в ядро как шум: исход одного боя симулятор не
предскажет, тенденцию серии — да.
