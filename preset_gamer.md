# Пресет OpenRouter для Cossacks 3

Два разных пресета, и путать их дорого.

## 1. `coss3-bot` — для МОСТА. Без system prompt

Мост шлёт свой `SYSTEM` (16 153 символа: команды, роли, формат ответа) и требует
строгий JSON. Любой чужой system prompt в пресете вступает с ним в спор, а спор
формата означает такт впустую: JSON не разобрался — команд в игру не ушло.

Поэтому в пресете для бота **поле System Prompt оставить ПУСТЫМ**, а пользу
взять там, где она реальна — в маршрутизации и параметрах:

| поле | значение | почему |
|---|---|---|	
| Name | `coss3 bot` | |
| Slug | `coss3-bot` | обращение: `@preset/coss3-bot` |
| Models | `deepseek/deepseek-v4.1-flash` | 24/39 на стенде, 1,9 с медиана |
| System Prompt | пусто (проверено: для бота поле инертно) | свой шлёт мост, и он сильнее |
| Temperature | 0.4 | как в `ask()`; выше — разнообразнее, не умнее |
| Max tokens | 1200 | ответ обрезается — команд не будет |
| Provider · Ignore | `Morph`, `Io Net` | замеры 11.09 и 12.09, см. ниже |

Провайдеров занесли не по слухам, а по числам:

| провайдер | худший вызов | замер |
|---|---|---|
| Morph | 82 с | 11.09, 8 медленных решений из 14 |
| Io Net | 37,7 с | 12.09, все 5 вызовов мимо такта |
| DeepSeek | 2,9 с | 12.09, 12 вызовов |

Замер 18.09 по ВСЕМ трассам 17–18.09 (ферма base14/base15/parallel_start и
мак-тесты), 2 700 вызовов, по полю `provider`/`think_s` в `coss3_bot.jsonl`:

| провайдер | вызовов | медиана | худший | дольше 30 с |
|---|---|---|---|---|
| **DigitalOcean** | 122 | **16,9 с** | **269 с** | **19** |
| Relace | 258 | 6,1 с | 55 с | 5 |
| DeepInfra | 200 | 6,4 с | 30 с | 0 |
| Wafer | 70 | 3,8 с | 101 с | 3 |
| DeepSeek | 469 | 2,7 с | 18 с | 0 |
| Together | 150 | 2,0 с | 37 с | 1 |

**Кандидат в Ignore — DigitalOcean:** медиана съедает почти весь бюджет такта,
каждый шестой вызов дольше 30 с. Wafer по двум выбросам за партию сперва
попал под подозрение зря — медиана 3,8 с, это редкость, а не свойство.
Считать по всем трассам так: `provider` и `think_s` есть в каждом такте.

Бюджет такта при `--every 20` и скорости 1,38× — около 14 с.

Запуск с пресетом:

    python llm_policy.py --human --hints hints_human.txt --model @preset/coss3-bot --every 20 --ban market,academi

`--provider-ignore` тогда не нужен: маршрутизация уехала на сторону OpenRouter
и не зависит от того, вспомнил ли человек флаг.

Проверка одной командой:

    python llm_policy.py --check --model @preset/coss3-bot

`--check` знает про пресеты: каталог для них не сверяет, печатает ответ целиком
и прямо говорит, цел ли формат («ключ commands на месте») или пресет перебил
наш system prompt.

## 2. `genius-gamer` — для РУК

Этот пресет НЕ для бота. Он для того, чтобы спросить про партию самому.

### Что вставить в поле System Prompt — дословно, только это

```text
Ты — опытный игрок и игровой стратег. Помогай мне побеждать,
анализируя игровую ситуацию и предлагая конкретные действия.

Учитывай цель, правила игры, ресурсы, карту и действия противника.
Ищи нестандартные решения, но проверяй их реализуемость.
Не выдумывай игровые механики и информацию, которой у тебя нет.
Отделяй известные факты от предположений.

Отвечай в формате:
1. Краткая оценка ситуации.
2. Три следующих действия в порядке приоритета.
3. Главный риск и запасной план.

Если не хватает критически важных данных — задай уточняющий вопрос.
```

Остальные поля: Models — модель DeepSeek; параметры генерации по умолчанию.
Без выбранной модели пресет отдаёт 404.

### Как звать

```json
{"model": "@preset/genius-gamer",
 "messages": [{"role": "user",
   "content": "Cossacks 3, версия 2.2.3.92.6008. Настройки 1к 0пт, без рынка и пушек. Ситуация: ... Что делать дальше?"}]}
```

Давать ему настоящие числа из трассы, а не пересказ по памяти:
`python log_review.py --trace coss3_bot.jsonl` показывает обстановку каждого такта.

### Проверено на живом вызове 12.09: наш формат УЦЕЛЕЛ

Я предсказывал, что ролевой system prompt пресета перебьёт наш и сломает JSON.
**Замер это опроверг.** `--check --model @preset/genius-gamer`, три вызова через
трёх разных провайдеров (Modal, DeepSeek, Parasail), 2,2–3,3 с:

```
ответ: {'why': 'В начале партии нужно закрыть первое звено цепочки...',
        'ok': '', 'stuck': '', 'cause': '',
        'commands': [{'cmd': 'BUILD', 'role': 'mill', 'total': 1},
                     {'cmd': 'TRAIN', 'role': 'peasant', 'total': -1}, ...]}
формат ответа ЦЕЛ: ключ commands на месте
```

Значит system prompt, заданный в запросе (`messages=[{system: SYSTEM}, ...]`),
оказывается сильнее того, что лежит в пресете. Перебивает ли его OpenRouter,
или модель просто выбрала более конкретную инструкцию — по одному замеру не
различить, и утверждать не буду.

**Практический вывод меняется.** Бояться поля System Prompt в пресете не надо:
для нашего бота оно инертно. Но и пользы от него нет — заполнять его для
`coss3-bot` незачем. Ценность пресета для петли ровно в другом: модель,
параметры и маршрутизация провайдеров, которую иначе приходится помнить флагом.

Три причины ниже остаются верными для СОБЕСЕДНИКА: если звать пресет своим
запросом БЕЗ нашего system prompt, ответ придёт в его формате, и петля с таким
ответом ничего не сделает.

1. **формат.** Разбор берёт последний разбираемый объект в тексте. Ответ из трёх
   нумерованных разделов не даст ни одной команды;
2. **уточняющий вопрос.** «Если не хватает данных — задай уточняющий вопрос» в
   петле на 20 игровых секунд задавать некому. Такт потерян;
3. **три действия по приоритету.** Наши команды декларативные и удерживаются
   каждый такт («хочу ВСЕГО N»), а не список приоритетов. Их до шести.

## Чего пресет НЕ делает

Сохранение пресета не применяет его к вызовам само: он подставляется только
через поле `model`. Наш `--model` передаёт строку как есть, так что
`@preset/<slug>` работает без правок кода.
