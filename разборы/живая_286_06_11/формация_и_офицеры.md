# Вопрос игрока «прожимается формация на отряд или бот просто водит всех?»

**Партия на (286), оборвана на 9:28.** Трасса `C:\coss3-io-286`.

## 1. Формация НАСТОЯЩАЯ — это состояние движка, не учёт моста

Имя строя в `squads_list` берётся из движка, `block_hstate:899`:

```pascal
var hssqfs : String = '-';
if (TSquad(hspsq).fFormation >= 0) then hssqfs := gFormation[TSquad(hspsq).fFormation].sid;
```

Стоит `SQUARE36` — значит у реального `TSquad` в движке `fFormation >= 0`, и таблица строёв
движка зовёт эту форму `SQUARE36`. Не прожалось бы — в поле был бы прочерк.

## 2. Доля армии в строю: до 7:03 — НОЛЬ, с 8:05 — до 86 %

## 3. Почему до 7:03 строя не было — ОФИЦЕРА НЕ БЫЛО

```
my_officers:  6:58 → 1    7:23 → 2    8:30 → 3    далее 2, далее 1 (гибнут)
первый отряд: 7:08 — через ДЕСЯТЬ СЕКУНД после первого офицера
```

**Правило «отряд на ходу» сработало так быстро, как физически возможно.** Узкое место —
срок офицера, то есть академия, а не сборка. Для слова игрока «жди первый отряд, потом
атака» связывающее ограничение именно это: **раньше 7:00 первой атаки с отрядом быть не
может по построению**.

Этим снимается то, что я чуть не доложил маку — «правило в дебюте не работает». Работает.

## 4. Дробление идёт по числу офицеров — уточнение к (287)

```
офицеров 1 (6:58)  →  отрядов 1   (7:08:  38 в SQUARE36)
офицеров 2 (7:23)  →  отрядов 2   (8:05:  1,27 + 2,38)
офицеров 3 (8:30)  →  отрядов 3   (8:50:  1,11 + 2,18 + 3,38)
```

(266а) `отрядов` 3 нанимает следующую пару, пока отрядов меньше трёх, а новая сборка берёт
«36 ближайших к точке» **из тех же людей**. Каждый новый офицер режет существующий отряд.

**И поправка к моему же слову «раздробили»:** люди не выпали из строя — их **разделили между
строями**. В отрядах к концу 61–67 человек, но кусками: 11 в `SQUARE36` (почти пустое каре)
и 18 в `SQUARE15`. Беда не «бот водит всех», а «одно сильное каре стало тремя слабыми».
