# Начало сессии: Cossacks 3

Проект большой и писан слоями: одиннадцать документов, две тысячи строк в одном
только `HANDOFF.md`. Читать всё не надо и вредно — поздние слои отменяют ранние.
Ниже порядок, который даёт понимание за несколько минут.

## Шаг 1. Прочитать ровно два файла

**Где репозиторий, зависит от машины:** на маке `~/coss3-bridge`, на Windows
`C:/Users/LapSt/Downloads/coss3-git`, в WSL `~/coss3-git`. Дальше он зовётся
просто «репозиторий».

1. **`RESUME.md`** — источник правды: состояние дел, контрольные
   числа установки, команды запуска, что делать дальше. В нём же таблица «какому
   документу что верить».
2. **память проекта** (`MEMORY.md` и `coss3-stop-*.md`) — где остановились и
   чем это кончилось.

Всё остальное — по ссылке из `RESUME`, когда понадобится. `WORKLOG.md` —
хронология с причинами каждой правки, ищите датой. `world.md` — знание, которое
уходит модели. `HANDOFF.md` — справочник по движку, но §1–§5 про компьютерный
слот и устарели.

**Чему НЕ верить:** `README.md` (прежняя, компьютерная конструкция, не
ставится), `MORNING.md` (план утра 12.09, пройден целиком), `lessons_verdict.md`
(приговоры вынесены на компьютерном слоте), `PROGRESS.md` (история разбора
движка; карта v2 оттуда на человеческий слот не переехала).

## Шаг 2. Проверить, где мы на самом деле

Документы отстают от кода — код отстаёт от живой игры. Пять команд, две минуты:

```bash
cd <репозиторий>
git log --oneline -3                     # что сделано последним
git log --oneline -1 verified            # какая версия проверена живой игрой
git status --short                       # есть ли незакоммиченное
# последние прогоны. На маке — через gh:
gh api "repos/snipstack-cloud/coss3-results/commits?sha=results&per_page=3" \
   --jq '.[] | "\(.commit.committer.date)  \(.commit.message | split("\n")[0])"'
# НА WINDOWS gh НЕ УСТАНОВЛЕН — 16.09 на это ушло время. Там результаты
# берут из клона в WSL, тем же ключом, которым ходят контейнеры:
#   wsl -e bash -c 'cd ~/coss3-results && git pull -q && git log --oneline -3'
#   (ключ подставляется через GIT_SSH_COMMAND с ~/.ssh/coss3_results)
grep -n "^\[" docker/experiments.ini | tail -5   # последние заведённые идеи
```

**Метка `verified` — главное число сессии.** Контейнеры берут мост по ней, и
двигается она только после проверки на живой игре на Windows. Если `master`
ушёл вперёд метки — там лежит непроверенное, и ферма его не возьмёт.

## Шаг 3. Понять, кто что делает

| где | что там | кто |
|---|---|---|
| мак, `~/coss3-bridge` | мастер репозитория, правки, статические проверки, разбор результатов | я |
| Windows, `C:\Users\LapSt\Downloads\coss3-git` | ЖИВАЯ игра: установка блоков, проверка пульса, ручные команды | игрок |
| WSL на той же машине | контейнеры с игрой под Wine, серии опытов | игрок запускает, я разбираю |
| `snipstack-cloud/coss3-bridge` | мост, приватный. Windows и контейнеры тянут отсюда | |
| `snipstack-cloud/coss3-results` | результаты прогонов, ветка `results`. С мака доступен через `gh`, не по ssh | |

Игра под Wine на Apple Silicon не запускается — ветка закрыта, проверять только
на Windows.

## Шаг 4. Взять нужный скилл

* **правка моста** — `coss3-human-bot`: семь шагов от «можно ли это сделать в
  python» до метки `verified`, список смертельных форм `.inc` и что ловит
  верификатор;
* **запуск серии в контейнерах** — `coss3-farm`: что проверить до старта, шаблон
  запуска, четыре строки лога, по которым видно, что проверяется задуманное;
* **разбор прогона или серии** — `coss3-results`: контроль, счёт инструментом,
  ловушки счёта, чему верить в словах модели и критика.

* **закрытие сессии** — `coss3-stop`: что дописать и проверить, чтобы следующая
  сессия не потеряла нить. Брать ВСЕГДА перед уходом, особенно если крутится
  прогон или метка `verified` отстаёт: дороже всего теряются не находки, а то,
  что проверено, где стоит метка и какие плечи недосравнены;
* **тест контейнера на маке** — `coss3-mac-test`: только для мака, на Windows
  не годится и с `coss3-farm` не путать.

Копии всех лежат в репозитории (`SKILL_начало.md`, `SKILL_мост.md`,
`SKILL_ферма.md`, `SKILL_разбор.md`, `SKILL_конец.md`, `SKILL_мак.md`), чтобы
порядок работы был версионирован рядом с кодом.

**Скиллы живут ПО МАШИНАМ** — в `~/.claude/skills`, на Windows в
`%USERPROFILE%\.claude\skills`. Работа идёт на трёх машинах сразу, и после
сброса сессии на любой из них скиллов может не оказаться. Поднимаются из
репозитория одной командой:

```bash
git pull && python install_skills.py
```

Скиллы читаются при СТАРТЕ сессии, поэтому после установки сессию надо начать
заново — в текущей они не появятся. Пока не появились, порядок работы читается
глазами: те же файлы `SKILL_*.md` лежат в корне репозитория.

## Три правила, которые нарушаются чаще всего именно в начале

1. **Не двигать метку `verified` без живой игры.** Она защищает ферму от моста,
   который не компилируется.
2. **`.inc` проверять только на Windows.** Контейнер для этого негоден: цикл три
   минуты, экран чёрный, а «ПУЛЬСА НЕТ» имеет три разные причины.
3. **Смотреть, что лежит в УСТАНОВЛЕННОМ файле игры, а не в репозитории.**
   14.09 дважды подряд ставилось не то, что думали: протухшая локальная метка
   (`git pull` не двигает уже существующую — нужен `git fetch --tags --force`) и
   detached HEAD, где `git pull` молча ничего не делает.

## Что это вообще за проект, в пяти строках

Модель играет в Cossacks 3 **человеческим слотом** — по правилам хакатона
нативный ИИ выключен, блоки моста стоят в `progress.inc` и `doprogress.inc`,
обмен через `.dat`-файлы. Цель партии: убить хотя бы одного крестьянина врага за
15 игровых минут. Берётся примерно в одной партии из пяти-десяти, и это честное
число — захват крестьян запрещён настройками.

Работа идёт кругом: модель играет → мост говорит вслух, что не вышло → модель
называет причину → проверяем по коду и трассам → знание в `world.md` → замер
серией на ферме → подтверждённое в `hints_human.txt`. Полный круг прошли две
вещи: ранняя шахта железа и механика убегающего крестьянина.

**Главное правило проекта, из которого следует почти всё:** модель ошибается
ровно настолько, насколько врёт описание мира. Прежде чем чинить модель —
проверь состояние.
